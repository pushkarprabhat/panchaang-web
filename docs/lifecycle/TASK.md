# Work item template

Copy this into the Plane description.

## Header

- Type: Feature | Bug | Spike | Docs | Ops | Content
- Project:
- Cycle:
- Parent:
- Blocks:
- Blocked by:
- Relates to:

## Requirement

Who needs this, and what they can do when it is done. One paragraph.

## Refinement

- In scope:
- Out of scope:
- Acceptance checks:
- Data or city rule, if any:

## Artefacts by type

| Type | Required before Ready | Required before Done |
| --- | --- | --- |
| Feature | Acceptance checks | PR link, staging URL, production check |
| Bug | Failing case | PR link, the case now passes |
| Spike | Question to answer | Decision note, follow-up item or Cancelled |
| Docs | Page list | Page URL |
| Ops | Change and rollback | Evidence the change is live |
| Content | Source and city or state tag | Page or data file link |

## Definition of Ready

- Outcome is one sentence.
- Acceptance checks are testable.
- Out of scope is named.
- Blockers are linked.

## Definition of Done

- Acceptance checks pass.
- PR is merged to the integration branch.
- Staging was seen, or the change has no UI.
- Production approval is recorded on the item.
- User-facing copy does not promise a payment path that is not live.
